## Why this folder exists

Several AI systems and David are independently examining the same architectural
question. Their proposals overlap substantially, but they do not use identical
categories or draw every boundary in the same place.

This folder puts the resolution process in front of everyone. It preserves the
agreements, the genuine disagreements, and the final human rulings in a location
that every participant can inspect.

GitHub is the **source of record for the architecture round**. It is not the
source of truth. A merge records the current governed decision; it does not make
a theological, historical, scientific, or bridge claim true.

## Resolution workflow

1. Each participant reads the same source packet.
2. Each participant submits an independent response using the template.
3. Shared conclusions are added to the consensus draft.
4. Genuine differences are added to the open-rulings ledger without being
   silently averaged away.
5. David records a ruling, requests another adversarial round, or leaves the
   question open.
6. Only after explicit approval is the accepted architecture implemented in the
   working vault.
7. Implementation receives a separate receipt listing created, copied, linked,
   and unchanged files.

## Non-negotiable boundary

The architecture must keep these different:

- God, the intended ontological referent;
- **God Is**, the admitted root proposition or confession;
- the identification of that referent through revelation;
- claims about divine nature and character;
- claims about divine capacity;
- claims about divine acts;
- conceptual or formal derivations;
- historical and empirical evidence; and
- cross-domain bridges.

If two statements can fail separately, the architecture must permit them to be
stored, tested, and revised separately.
